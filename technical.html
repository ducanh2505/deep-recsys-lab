01 · Raw sources

The original rows keep context.

Raw MovieLens files are human-readable tables. The preparation step uses the rating and catalog keys to build implicit feedback.

Raw field contract

Types shown here describe the source semantics before pandas loading.

FieldSource typeRequiredMeaning and downstream use
userIdintegeryesUser identity used to count histories and assign train / validation / test users.
movieIdintegeryesCatalog identity used to construct the item mapping.

Transformation rules

  1. 01

    Filter positives: keep rows where rating ≥ 4.0.

  2. 02

    Require history: keep users with at least 5 positive ratings.

  3. 03

    Split users: deterministic seeded permutation assigns 116,677 train, 10,000 validation, and 10,000 test users.

  4. 04

    Build catalog: model columns come from unique positive movies seen by training users; this produces 20,108 items.

03 · Training data

Sparse on disk, dense per batch.

Training stores only positive events. The dataset adapter expands each CSR row into a dense float32 tensor before the Multi-VAE sees it.

Python · training loadersrc/deep_recsys_lab/cli.py
prepared = load_prepared_data("data/processed")
train_loader = DataLoader(
    InteractionDataset(prepared.train),
    batch_size=500,
    shuffle=True,
)

batch = next(iter(train_loader))
batch["data"].shape          # torch.Size([500, 20108])
batch["data"].dtype          # torch.float32
batch["data"].unique()         # tensor([0., 1.])

Training tensor contract

ValueContract
batch["data"][B, n_items] dense tensor, dtype float32.
targetThe same binary vector is used as the multinomial reconstruction target.
row value1.0 means a positive interaction; 0.0 means unobserved.

04 · Evaluation data

Every score has a seen set and a truth set.

Validation and test users are split into fold-in history for the model input and fold-out positives for ranking metrics.

Python · deterministic evaluation datasetfold-in + fold-out
validation_dataset = InteractionDataset(
    prepared.validation_fold_in,
    eval=True,
    fold_in=prepared.validation_fold_in,
    fold_out=prepared.validation_fold_out,
)

batch = next(iter(DataLoader(validation_dataset, batch_size=500)))
batch["data"]           # fold-in: what the model is allowed to see
batch["ground_truth"]   # fold-out: positives used for Recall / NDCG

A single evaluation row

Fold-in and fold-out have the same [n_items] shape and never overlap for a user.

item column
01234
fold-in
10010
fold-out
01001

What evaluation does

  1. 01

    Score: model emits logits with shape [B, 20,108].

  2. 02

    Mask: set fold-in items to negative infinity so known items cannot be recommended.

  3. 03

    Rank: take sorted unseen top-k indices.

  4. 04

    Measure: compare ranked indices only against fold-out positives.

05 · Serving boundary

The API accepts IDs, not tensors.

The class-based BentoML Service loads one explicit Model Store version per CPU worker, reconstructs a binary history row, scores unseen items, and joins the result to metadata.

Request

POST /recommend

JSON 
{
  "movie_ids": [1, 2, 50, 110, 260],
  "top_k": 3
}

The request requires 5–500 unique known IDs. Optional X-API-Key auth is enforced when configured.

Response

Sorted, unseen recommendation records.

JSON 
{
  "request_id": "request-123",
  "model_version": "movielens-cpu-smoke-v1",
  "recommendations": [{
    "movie_id": 318,
    "title": "Shawshank Redemption, The (1994)",
    "genres": "Crime|Drama",
    "score": 4.218
  }]
}

Score note: ranking logits are uncalibrated; they are not probabilities.
