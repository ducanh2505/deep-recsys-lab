01 · Idea of the approach

Recommend from behavior, not profiles.

The system is collaborative filtering: it learns recurring co-consumption patterns across users. Titles and genres are returned as metadata, but they are not model features.

x

Behavior becomes a vector

Each user is represented by a binary item vector. A 1 means a rating of at least 4.0; a 0 means the item is unobserved, not necessarily disliked.

z

Taste becomes a distribution

Multi-VAE compresses the sparse history into a 200-dimensional posterior. Sampling regularizes training; the posterior mean makes evaluation and serving deterministic.

k

Prediction becomes ranking

The decoder scores every catalog item at once. Known items are masked, then the highest logits become top-k recommendations. Scores are ranking signals, not probabilities.

i
Core assumption Users with overlapping positive histories are likely to value similar unseen items. The model learns this overlap nonlinearly, without requiring a persistent user ID at inference time.

03 · Model

Multi-VAE learns a compact preference space.

This is the multinomial variational autoencoder for collaborative filtering described by Liang et al. (2018), implemented with tanh layers, L2 input normalization, and a Gaussian latent posterior.

Forward path

One row per user · all catalog items scored together

Before encodingL2 normalize each row, then apply 0.5 input dropout during training.
During trainingReparameterize z = μ + εσ to learn a smooth latent preference space.
During evaluationUse z = μ, eliminating sampling noise for repeatable rankings.
Optimization objectiveMultinomial reconstruction rewards probability mass on observed positives; annealed KL regularization keeps the posterior close to a standard normal prior.
L = NLLmult + β · KL(q(z|x) || N(0,I))

04 · Training

Train, validate, checkpoint, repeat.

Runs are seeded and metadata-rich. Adam optimizes dense user batches, β rises linearly toward its cap, and the best checkpoint is selected by validation NDCG@100.

one training run

02
Optimize batchesDense float32 rows pass through Multi-VAE with sampling; Adam updates from NLL + β·KL.
03
Validate every epochUse posterior means, mask fold-in items, and compute Recall and NDCG at 20, 50, and 100.
04
Persist progressWrite metrics.jsonl and last.pt; update best.pt when validation NDCG@100 improves.

05 · Inference

Known movies in. Unseen rankings out.

Serving is stateless. BentoML resolves one explicit Model Store tag, validates it at startup, and returns a deterministic ranking for each MovieLens history.

01 / LOAD

Validate Bento model

Resolve an explicit tag and verify schema v2, checksums, item order, metadata, weights, and tensor shapes.

02 / MAP

Resolve IDs

Reject unknown movie IDs and map known IDs to model-column positions.

03 / VECTOR

Build history

Create one float32 binary row with 1s at the supplied movie positions.

04 / SCORE

Decode logits

Run inference_mode with sample=false, so z equals the posterior mean μ.

05 / MASK

Remove seen

Exclude every supplied history item from the candidate ranking.

06 / TOP-K

Return results

Sort unseen logits and attach movie ID, title, genres, and score.

Request contract

A known-item history and the desired ranking length. Every movie ID must exist in the registered item mapping.

POST /recommend · { movie_ids: [...], top_k: 20 }

Response contract

Ranked unseen movies, model version, and request ID. The API can optionally require an API key.

{ movie_id, title, genres, score } × top_k
!Recommendation scores are uncalibrated logits. Compare them only for ordering within the same request; do not read them as probabilities or confidence percentages.

07 · Current scope

What V1 proves—and what it does not.

The methodology is implemented end to end and validated through bounded runs. Scientific claims remain deliberately narrower than the engineering coverage.

Implemented and checked

  • ✓Complete MovieLens preprocessing with the expected 20,108-item catalog.
  • ✓Multi-VAE forward pass, loss, KL schedule, checkpointing, and deterministic ranking metrics.
  • ✓Synthetic end-to-end smoke path through training, Bento model registration, and API prediction.
  • ✓Immutable schema-v2 Model Store artifacts and a class-based BentoML Service with native health, metrics, and OpenAPI.

Important boundaries

  • !No completed full 200-epoch paper reproduction is claimed yet.
  • !The model is collaborative only: no title, genre, text, temporal, or contextual features.
  • !Unknown items cannot be scored, and empty or very short histories remain a cold-start limitation.
  • !MovieLens is research data with separate usage restrictions; it is not bundled or redistributed here.
