01 · Data format

Two raw tables. One sparse artifact.

Ratings become binary positive interactions after filtering, then move into CSR matrices for training and evaluation.

Interaction source

One row per user–movie rating.

ratings.csv
userId int64 Stable user identifier
movieId int64 Movie identifier from the catalog
rating float32 Explicit rating from 0.5 to 5.0
timestamp int64 Unix time for the original event

Catalog source

Display metadata for each movie.

movies.csv
movieId int64 Join key used by ratings
title string Movie title with release year
genres string Pipe-separated genre labels
→ processed JSON movie_id, title, and genres

Prepared matrices

Binary CSR arrays consumed by training.

*.npz
train CSR User × item training history
validation CSR × 2 fold-in input and held-out truth
test CSR × 2 fold-in input and held-out truth
values float32 All stored interactions are 1.0

Stable lookup contract

Maps model columns back to source metadata.

item_ids.npy
column index int Position in every matrix row
item ID int64 Original MovieLens movieId
manifest JSON Schema, checksums, config, statistics
integrity SHA-256 Hash recorded for every artifact
